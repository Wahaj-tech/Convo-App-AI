========================================================
  CONVO-APP: AI-NATIVE COLLABORATION PLATFORM
  IMPLEMENTATION PLAN
========================================================

CONTEXT
-------
Convo-App is currently a solid 1-on-1 real-time chat app
(React + Express + MongoDB + Socket.io). The goal is to
transform it into an AI-native collaboration platform
where AI is a first-class conversation participant -- not
a sidebar chatbot. This involves 4 phases: group chats,
@AI integration, conversation memory, and AI personas.
Each phase builds on the previous.


========================================================
PHASE 1: CONVERSATION MODEL + GROUP CHATS
========================================================

WHY: The current architecture is strictly 1-on-1
(senderId/receiverId on every message). We need a
Conversation container model before AI or groups work.

--------------------------------------------------------
1.1 New Model: backend/src/models/Conversation.js
--------------------------------------------------------

Schema fields:
  - type: String, enum ["direct", "group"], required
  - name: String (null for direct, required for group),
    maxlength 100
  - groupImage: String, default ""
  - members: [ObjectId ref User]
  - admin: ObjectId ref User (group creator; null for
    direct)
  - lastMessage: ObjectId ref Message
  - lastMessageAt: Date
  - timestamps: true

Index: compound on { members, type } with unique partial
filter for type="direct"

--------------------------------------------------------

  - Add conversationId: ObjectId ref Conversation,

  - Keep senderId (still needed)
  - Keep receiverId temporarily for migration, then
    deprecate
  - Add compound index on { conversationId, createdAt: -1 }

PHASE 2: @AI INTEGRATION WITH CLAUDE API
========================================================

WHY: This is the core innovation -- AI responds inline
in conversations with full context awareness.

--------------------------------------------------------
2.1 New Dependency
--------------------------------------------------------

  - @anthropic-ai/sdk added to backend/package.json
  - New env var: ANTHROPIC_API_KEY in
    backend/src/lib/env.js

--------------------------------------------------------
2.2 New Files
--------------------------------------------------------

  backend/src/lib/anthropic.js
    Initialize Anthropic client

  backend/src/services/ai.service.js
    Core AI logic:
    - detectAiMention(text) -- regex match @ai or
      @claude (case insensitive)
    - extractAiPrompt(text) -- strip the mention,
      return the query
    - buildConversationContext(messages, maxMessages=50)
      -- convert to Claude message format with
      [SenderName]: text
    - getAiResponse(context, systemPrompt) -- call
      Claude API (claude-sonnet-4-20250514, 1024
      max_tokens)

  backend/src/scripts/seedAiUser.js
    Create a sentinel AI user doc with fixed ObjectId
    for message attribution

--------------------------------------------------------
2.3 AI Message Pipeline (in message.controller.js)
--------------------------------------------------------

  User sends message
    -> save to DB
    -> emit via socket
    -> respond 200 immediately
    -> IF @AI detected:
       -> emit "aiTyping" to room
       -> fetch last 50 messages for context
       -> call Claude API
       -> save AI message (senderType: "ai")
       -> emit "aiTyping: false"
       -> emit "newMessage" with AI response

  Key: AI processing is async (fire-and-forget after
  HTTP response). User gets instant message
  confirmation, then sees AI typing indicator, then
  AI response arrives via socket.

--------------------------------------------------------
2.4 AI Rate Limiting
--------------------------------------------------------

  - Simple in-memory rate limiter: 20 AI calls per
    user per hour
  - backend/src/middleware/aiRateLimit.middleware.js
  - If limited, emit error message to conversation

--------------------------------------------------------
2.5 New Socket Events
--------------------------------------------------------

  - "aiTyping"  { conversationId, isTyping: boolean }
  - "aiError"   { conversationId, error: string }

--------------------------------------------------------
2.6 Frontend Changes
--------------------------------------------------------

    Render AI messages with distinct style

========================================================
PHASE 3: CONVERSATION MEMORY
========================================================

WHY: AI remembers past decisions across sessions.
"What did we decide about X last week?" actually works.

--------------------------------------------------------
3.1 New Model: backend/src/models/ConversationMemory.js
--------------------------------------------------------

  - conversationId: ObjectId ref Conversation, indexed
  - summary: String (AI-generated rolling summary)
  - keyDecisions: [{ decision, madeBy, timestamp,
    context }]
  - actionItems: [{ task, assignedTo,
    status: pending|in_progress|done, createdAt }]
  - topics: [String]
  - lastSummarizedAt: Date
  - lastSummarizedMessageId: ObjectId ref Message
  - totalMessagesProcessed: Number

--------------------------------------------------------
3.2 New Service: backend/src/services/memory.service.js
--------------------------------------------------------

  - getConversationMemory(conversationId)
    -- get or create
  - updateConversationSummary(conversationId)
    -- fetch messages since last summary, ask Claude
    to update structured summary (decisions, action
    items, topics)
  - buildAiContext(conversationId)
    -- combine memory summary + last 30 messages into
    a rich system prompt

--------------------------------------------------------
3.3 Modified AI Pipeline
--------------------------------------------------------

  - Before calling Claude, use buildAiContext() instead
    of raw messages
  - System prompt now includes: conversation summary,
    key decisions, pending action items
  - Trigger summarization when message count is 20+
    messages behind

--------------------------------------------------------
3.4 Summarization Job
--------------------------------------------------------

File: backend/src/jobs/summarization.job.js

  - setInterval every 30 min, processes conversations
    with unsummarized messages
  - Called from app.js after server.listen

--------------------------------------------------------
3.5 New API Route
--------------------------------------------------------

  GET /api/conversations/:id/memory
    Returns memory doc (summary, decisions, action
    items)
  Added to conversation.controller.js

--------------------------------------------------------
3.6 New Frontend Component
--------------------------------------------------------

  ConversationMemoryPanel.jsx
    Accessible from ChatHeader button. Shows summary,
    decisions, action items (with status toggles),
    topics. Users can see and correct what the AI
    "remembers."
